# Vaanimitra Scribe: API & Database Reference

## 1. REST API Endpoints

### 1.1 Client Endpoints
- `GET /`
  - Serves the main `index.html` application.
- `GET /config`
  - Returns VAD tuning parameters as JSON (used by `vad-web` on the client).
- `GET /api/exam/{exam_id}/questions`
  - Returns the exam metadata and all associated questions.
- `GET /api/session/{session_id}/answers`
  - Returns all `AnswerSegment` records for a specific session (used for recovering state).
- `POST /api/session/{session_id}/submit`
  - **Payload**: `{"answers": {"question_id": "text_content", ...}}`
  - **Action**: Marks session as submitted, purges raw segments, commits final compiled text, and triggers asynchronous PDF generation.
  - **Returns**: `{"status": "success", "pdf_url": "/api/session/{session_id}/pdf"}`
- `GET /api/session/{session_id}/pdf`
  - Generates (if not cached) and serves a styled, formatted PDF answer sheet using `reportlab`.

### 1.2 Admin Endpoints
- `GET /admin`
  - Serves the `admin.html` dashboard.
- `GET /api/admin/sessions`
  - Returns live tracking data for all sessions, including `student_name`, `status`, and `answer_count` (aggregated via SQL `COUNT()`).
- `GET /api/admin/exam/{exam_id}/status`
  - Returns `{ "status": "scheduled" | "onboarding" | "active" | "completed" }`.
- `POST /api/admin/exam/{exam_id}/onboard`
  - Updates DB to `status="onboarding"` and broadcasts `"start_onboarding"` to all connected WebSockets.
- `POST /api/admin/exam/{exam_id}/start`
  - Updates DB to `status="active"` and broadcasts `"exam_started"` to all connected WebSockets.
- `GET /api/session/{session_id}/audit`
  - Returns full `AuditLog` history for a specific student session.

## 2. WebSocket Protocol (`/ws`)
*For a high-level overview of how data flows through these sockets, see [[02_data_flow_and_state|Data Flow & State Management]].*

### 2.1 Connection Flow
1. Client connects to `wss://[host]/ws?session_id=[optional_uuid]`.
2. Server responds with `{"type": "session_init", "session_id": "..."}`.
3. Server immediately pushes `{"type": "exam_load", ...}` containing all exam questions and an `is_registered` boolean flag.
4. Server immediately pushes the current exam state (`exam_started`, `start_onboarding`, or `exam_waiting`).

### 2.2 Messages Received by Server
- **Raw Audio Chunk**:
  - `{"type": "audio", "data": "base64...", "context": {...}}`
  - `context` includes: `question_index`, `exam_state`, `registration_phase`.
- **Question Navigation Sync**:
  - `{"type": "set_question", "question_id": "..."}`
  - Updates `current_question_id` on the server so incoming audio is bound to the correct question.
- **Student Lookup (Registration)**:
  - `{"type": "lookup_student", "reg_no": "..."}`
- **Legacy Registration Submission**:
  - `{"type": "register", "name": "...", "reg_no": "..."}`

### 2.3 Messages Sent by Server
- **Transcript Result**:
  - `{"type": "transcript", "text": "...", "words": [...], "inference_ms": ...}`
  - `words` array contains per-word confidences (used to underline low-confidence words in red).
- **Command Result**:
  - `{"type": "command", "intent": "nav_next", "target": null, ...}`
  - If it's a destructive command (e.g., `submit_exam`), it includes `requires_tts_confirm: true`.
- **Error / Empty**:
  - `{"type": "error", "message": "..."}`
  - `{"type": "empty", "inference_ms": ...}` (Fired when VAD sends audio but Whisper detects no speech).
- **Registration Flow**:
  - `{"type": "student_found", "name": "...", "reg_no": "..."}`
  - `{"type": "student_not_found", "reg_no": "..."}`

## 3. Database Schema
Defined in `server/database.py` using SQLAlchemy async ORM.

### `Exam` Table
- `id` (String, PK): UUID.
- `subject` (String): e.g., "Design and Analysis of Algorithms".
- `course_code` (String).
- `duration_minutes` (Integer).
- `status` (String): "scheduled", "onboarding", "active", "completed".

### `Question` Table
- `id` (String, PK).
- `exam_id` (FK -> exams.id).
- `q_number` (Integer).
- `part` (String): "A", "B", etc.
- `text` (Text).
- `marks` (Integer).

### `Student` Table
- `id` (String, PK).
- `name` (String).
- `roll_no` (String, Unique).
- `disability_type` (String).

### `Session` Table
- `id` (String, PK): UUID generated by WS.
- `student_id` (String, nullable): FK to students.id.
- `student_name` (String, nullable): Filled during registration.
- `reg_no` (String, nullable): Filled during registration.
- `status` (String): "active", "submitted", "abandoned".
- `submitted_at` (DateTime, nullable).

### `AnswerSegment` Table
- `id` (Integer, PK).
- `session_id` (FK -> sessions.id).
- `question_id` (FK -> questions.id).
- `text` (Text): The raw dictated text chunk.
- `sequence_number` (Integer): Used to reassemble chunks in chronological order.

### `AuditLog` Table
- `id` (Integer, PK).
- `session_id` (FK -> sessions.id).
- `utterance_type` (String): "transcript" or "command".
- `raw_text` (Text): Exact text Whisper transcribed.
- `confidence_avg` (Float): Average probability of words.

## 4. PDF Generation Architecture (`pdf_generator.py`)
1. Executed dynamically when the `/api/session/{id}/pdf` endpoint is hit.
2. Queries the `Session`, `Exam`, `Question`, and `AnswerSegment` tables.
3. Uses `reportlab` to construct a professional, styled A4 document.
4. Answers are compiled by concatenating all `AnswerSegment` texts for a given `question_id`, ordered by `sequence_number`.
5. Includes metadata like the student's name, register number, and submission timestamp.
6. Writes the PDF locally to `answers/{session_id}.pdf` and returns the binary stream to the browser.
